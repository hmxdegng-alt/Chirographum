# Chirographum — notes for working on the code

Desktop editor (Electron + Vite + TypeScript, no UI framework) that writes and prints text in the user's own handwriting. AGPL-3.0. Windows first.

## Rules that never change
- The app never touches the network: `electron/network-guard.cjs` (dead proxy, host resolver rules, webRequest filter, permissions, navigation lock). Do not add anything that downloads, updates or reports.
- Code and comments in English, comments only where they help. Every user-facing text in Spanish, in `src/i18n/es.ts`.
- Pens and pencils never get darker where strokes cross (tone mask merged with "lighten"); markers and highlighters do (stacked layers).
- A letter's look comes from its identity (`src/engine/char-ids.ts`), never from its position, so editing does not redraw the rest of the page. The one exception is `nat.fatigue` ("Cansancio"): it scales each letter's deviations by how far down the text it is, smoothly, so an edit only nudges what follows.
- Hands (`.chmano`) and documents (`.chiro`) are separate files on purpose.

## Versions
`vX.Y.Z`: X = final release (0 until 1.0), Y = development phase, Z = builds within the phase. Bump `version` in package.json and package-lock.json (root and `packages[""]`). The owner publishes a GitHub release with the tag; `.github/workflows/build.yml` builds the Windows installer and attaches it.

## Map
- `electron/main.cjs` window, menus (Archivo, Editar, Formato, Ver), IPC, unsaved-changes prompt, single instance, `.chiro` opening; `electron/preload.cjs` → `window.chirographum` (types in `src/bridge.ts`).
- `src/engine/scribble.ts`: the five kinds of scribble (rayajos, rayas, ida y vuelta, cruz, bucles) modelled on the owner's sample sheet; "rabia" 0–1 sets how much ink. The toolbar menu draws its previews with the same code.
- `src/engine/` pure logic: `hand.ts`, `geometry.ts`, `layout.ts` (glyph placement, caret stops, pages, styles, alignment, decorations, ruled paper), `render.ts` (ink model, printed look, paper; one ink group per instrument + colour), `pens.ts`, `settings.ts`, `rich-text.ts` (marks and paragraph formats), `document.ts`, `char-ids.ts`, `random.ts`.
- Character marks are 32-bit: bits 0–5 flags (bold, italic, underline, strike, highlight, scribble), 6–8 highlighter colour, 17–19 correction (`CORRECTIONS`: tipex, over, erase, above, below; typed letters never inherit it), 9–16 run style = index+1 into `runStyles` (instrument, colour, size and scribble look of a selection; 0 = the defaults). Only the toolbar sets instrument and colour; the document's `penId`/`inkColor` are just the base for unstyled text and have no control of their own (choosing them stores no style). Documents store them as `marks32`; 0.1 files had one byte per letter (`marks`, read with `upgradeMarkV1`). Unused run styles are dropped on save.
- Paragraph styles and alignment are per paragraph on purpose (as in Docs/Word); size per selection covers "only these words bigger".
- `src/ui/`: `draw-view.ts` (Tu letra), `sheet-view.ts` (Hoja: state, undo, commands, output, the settings panel), `page-editor.ts` (hidden textarea + drawn caret), `toolbar.ts`, `ruler.ts`, `zoom.ts`, `color-picker.ts` (the app's own picker; Chromium's cannot be closed from the page), `document-controller.ts`.
- Settings panel: collapsible sections with a "Restablecer" button each, a search box (`data-search`, compared without accents through `searchKey`), and `slider({ defaultValue })` adds the ↺ reset. Every new setting needs a default to go back to, and a usual range (`USUAL` in `sheet-view.ts`, `slider({ usual, caution })`): past it the slider turns yellow, then red. Only a hint, never a limit.
- Sliders call `onInput` on release ("change"), never while dragging (redrawing the page there makes them stutter); `live` is for cheap previews only.
- Highlighter: one decoration per run of the same colour; render splits it into sweeps of 3–7 cm that restart a little behind (darker overlap). Chisel ends by default (`StrokeGeometry.chisel`, one band with darker edges; each end roughly straight but irregular: own lean, bulge, wobble, softened corners), round with `highlightRound`; darker where the tip rests (a gradient inside the band, more often at the end). Word by word (`highlightWords` in the run style) stops near each word. `nat.highlighterSmear` × `pen.smear` drags ink; `nat.handSmudges` × 3 × `pen.smudge` (×3 and sideways for `leftHanded`; bigger and darker past 100 %) leaves hand smudges. Smudges widen the box `renderPage` returns, so printing does not crop them.
- Corrections: "over"/"erase" letters send the pen back (`placeWord` → the next letters go on top; a space right after them does not count); erased letters render with `rubbedOut` (faint ghost) and pencil gets an eraser haze; "above"/"below" words are placed smaller half way to the next line (the ruled pitch on lined paper), centred on the gap they go into, no caret.
- Correction tape ("tipex"): always `TAPE_WIDTH_MM` wide whatever the letter size, laid very straight (a slight angle; only pieces over 45 mm bend), overlapping passes when the letters are taller than the tape (`tapePasses` in render). `tapeSpan` gives where it starts and ends. Ends are cut straight, torn on the dispenser's teeth, or leave a strip of tape sticking out. Drawn under the ink (it hides ruled lines) with a hairline edge and a faint shadow. `inkOnTape` turns ink inside the tape grey and hollow (dark rims, thin silvery middle, beading), as on the owner's sample "prebas de boli y lapiz.jpg". The text written before the tape is `tipexUnder` in the run style: `placeUnderTape` lays it under the first piece of tape of the run (`LayoutResult.hidden`, not part of the text), cut where the tape ends; render draws it apart and puts it under the tape. The dialog (`tipex-dialog.ts`) refuses what does not fit, measured in millimetres with the real letters. Applying tape to letters that were not on tape, or another correction, clears `tipexUnder`. The tape is opaque white in the image, but printers have no white ink: it only works on white paper, so the sheet warns when tape goes onto a real notebook (paper lines not printed).
- Clipboard: copying from the page puts the text plus a `RichClip` (marks with their run styles, paragraph formats) under `RICH_CLIP_TYPE`; pasting it back (`parseRichClip` checks it belongs to the same text, `adoptClipMarks` finds or adds the run styles) restores the look. "Pegar sin formato" (Ctrl+Shift+V, menus) takes the formatting at the cursor, as in Docs. The page cannot read the clipboard: menus ask the main process (`edit:run` → `webContents.cut/copy/paste`) and the textarea's own clipboard events do the rest. `page-editor.replaceSelection` is the one way to put text in by code (undo works as for typing).
- Right-click menu (`context-menu.ts`, icons in `icons.ts`, never emoji): Cortar, Copiar, Pegar, Pegar sin formato, Eliminar, Opciones de formato ▸ (bold, italic, underline, strike, the four alignments), Borrar formato.
- Lines as by hand (v0.2.8): every `LineState` has its own `left`/`right` margins. `nat.blockTilt` turns the whole block of a page (up to `BLOCK_TILT_DEG` at 100 %, a different amount per page, usually the same way): lines get the slope and their start and right limit move sideways by `(baseline − page middle) × tan`; never on ruled paper. `page.paragraphIndentMm` indents the first line of every normal left/justified paragraph except the first one and the one after a heading, by `handIndent` (varies with `marginDrift`); spaces or a Tab at the start of a paragraph move the pen instead (Tab = the indent, or `TAB_INDENT_MM`). A word that does not fit (`fitAtEdge`, decided per word from its identity): crammed (`nat.wordSqueeze`: `placeWord(…, squeeze)` makes letters from a third of the way in narrower — `PlacedGlyph.narrow`, applied in `glyphPointToPage` —, closer, a bit smaller and rising, as in the owner's "carta boli normal.jpg"), or split by syllables (`nat.hyphenation`, `src/engine/hyphenate.ts`, Spanish rules, words of `MIN_SPLIT_LETTERS`+ only) with `AUTO_HYPHEN`, drawn with the hand's own "-" or `variantsOf`'s fallback dash; the rest goes on the next line. Words with corrections are never squeezed or split.
- Justified paragraphs: `justifyLine` in layout spreads only the gaps between words (never inside words, never the spaces that do not move the pen or those between words added above/below) to reach the right margin give or take `edgeJitter`; the last line of a paragraph stays left.
- Highlighter tip: `HIGHLIGHT_TIP_MM` wide whatever the letter size; letters taller than it get more passes (`highlightPasses`), every other one drawn back the other way.
- Smudges and the highlighter's drag also reach underlines, strikethroughs and scribbles (`markStrokes` in render, `smudgeMarks`/`smearMarks` in the settings, a checkbox under each slider); the future free drawing must stay out of them.
- `tipexInk` in the run style (slider in the correction menu, shown only with tape selected) sets how strong `inkOnTape` is for that piece of tape.
- Toolbar: the scribble and correction buttons only open their menus (the user should see what they pick every time); every "Quitar …" item in a menu is red, underlined, with a bin icon (`removeItem`); the correction menu shows a picture of each kind (`correctionPreview`) and greys out "Escribir debajo del Típex…" unless the selection is on tape.
- Presets: Calígrafo, Cuidadoso, Normal, Apuntes de clase, Con prisa, Cansado, Infantil, Letra de médico (in that order; every preset sets every naturalness value). `nat.inkBlobs` × `pen.blobProne` (ballpoints most, pencils never) leaves lumps of ink (`StrokeGeometry.lumps`: full tone in the mask plus a darker core over the ink).
- Wear (`penTuning.wear`, "Instrumento gastado"): `wornPen` makes pencils blunt, felt tips dry (`streaks`, drawn as pale lines into the tone mask) and pens run out (`dryness` → skips).
- Printing: quality Borrador/Normal/Alta (`PRINT_QUALITIES` in sheet-view): page image at 300 or 600 ppp; the resolution asked of the printer (`dpi` in `webContents.print`) picks the driver's quality mode. Fingerprints were tried and dropped (they printed as obvious dot patterns).
- `build/installer.nsh`: the installer creates `Documents\Chirographum documents` (`customInstall`); uninstaller page with an unticked checkbox to delete `%APPDATA%\Chirographum` (never the documents folder). electron-builder runs makensis with `-WX`: keep everything inside the macros.
- Saving (`doc:save` in main, `electron/documents-folder.cjs`): a document with a file goes back to it; a new one goes straight into "Chirographum documents" named after its first words (`safeFileBase`, never replacing a file: `writeNewFile`/`candidateName`); "Guardar como" and "Abrir" always open the dialog in that folder. The app creates the folder at start and before saving if it is missing.

## Checking work
- `npx tsc --noEmit -p .`, `npx vitest run`, `npx vite build`.
- End-to-end: end scripts with `process.exit` after killing Electron (a lingering connection keeps node alive), and kill leftovers with `pkill -f "[e]lectron/dist/electron"` in a shell call of its own (the brackets keep pkill from matching itself, but any other text in the same call that spells the path, e.g. a heredoc, gets the shell killed). Run the built app under `xvfb-run` and drive it with puppeteer-core through `--remote-debugging-port`. Test hooks (ignored in the installed app): `CHIROGRAPHUM_TEST_USER_DATA`, `CHIROGRAPHUM_TEST_PDF_PATH`, `CHIROGRAPHUM_TEST_SAVE_PATH`, `CHIROGRAPHUM_TEST_OPEN_PATH`, `CHIROGRAPHUM_TEST_UNSAVED_CHOICE`, `CHIROGRAPHUM_TEST_DOCUMENTS` (stands for the user's Documents); `window.chirographumCommand(name)` runs menu commands; `window.chirographum.requestClose()` acts like the window's close button.
- The NSIS installer needs wine to build on Linux; let the GitHub workflow build it.
